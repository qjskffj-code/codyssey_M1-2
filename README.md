# 대전 관광 AI 비서

"성심당이 유명해지면 대전 관광객도 늘까?"
공개 데이터 **102개월치**를 직접 모아 답을 찾고, 그 데이터를 근거로만 대답하는 AI 비서.

> **프론트엔드** — https://codyssey-m1-2-theta.vercel.app
> **백엔드 API** — https://codyssey-m1-2-vix0.onrender.com
> **Swagger UI** — https://codyssey-m1-2-vix0.onrender.com/docs

---

## 1. 이 서비스가 푸는 문제

일반 챗봇에게 "요즘 대전 관광객 어때?"라고 물으면 일반론이 돌아온다.
이 서비스는 **내가 모은 데이터만 보고** 답한다.

```
공공데이터 수집 → 월별 데이터셋 정제 → Firestore 저장
                → 요약 계산(통계·추세·상관계수·사건)
                → 시스템 프롬프트에 주입 → GPT 답변 → 대화 자동 저장
```

핵심 설계 원칙 세 가지.

- **숫자만 주지 않고 한계도 같이 준다.** "이동통신 추정치라 중복 집계된다", "상관은 인과가 아니다"를 프롬프트에 함께 넣어 AI가 과장하지 않게 만들었다.
- **지표마다 집계 기간이 다르면 기간을 함께 답한다.** 외국인 방문자는 2020년부터, 중구 비중은 2024년부터만 있다.
- **사건(memo)을 함께 주입한다.** 이게 없으면 "2020년에 왜 줄었어?"에 "데이터에 없습니다"라고 답한다.

## 2. 데이터로 확인한 것

처음 가설은 "성심당 인기 ↑ → 대전 관광객 ↑"였다. 실제로 계산해 보니 **어떤 데이터를 쓰느냐에 따라 결론이 달라졌다.**

| 주 지표 | 성심당 검색 지수와의 상관계수 | 해석 |
|---|---|---|
| 관광지점 입장객 통계 (공식 집계) | **-0.05** | 관계 없음 |
| **대전 외지인 방문자** (이동통신) | **+0.47** | 뚜렷한 양의 상관 |
| **대전 외국인 방문자** (이동통신) | **+0.78** | 강한 양의 상관 |

입장객 통계는 과학관·박물관 등 특정 시설만 집계해서 원도심 방문 흐름을 담지 못했다.
게다가 2023년 12월에 집계 대상 관광지 8곳이 빠져 **2024년에 방문객이 반토막 난 것처럼 보이는 함정**이 있었다.
그래서 주 지표를 이동통신 기반 방문자 수로 교체했다.

공간적으로도 확인했다. 성심당 본점이 있는 **중구만 다른 구보다 빠르게 성장**했다.

| 구 | 2024년 일평균 | 2025년 일평균 | 증가율 |
|---|---|---|---|
| **중구** (성심당 본점) | 122,889 | 134,999 | **+9.9%** |
| 동구 | 113,921 | 120,718 | +6.0% |
| 서구 | 170,819 | 181,230 | +6.1% |
| 유성구 | 166,439 | 175,079 | +5.2% |
| 대덕구 | 73,884 | 78,218 | +5.9% |

다만 **월 단위 등락은 함께 움직이지 않는다.** 검색량은 뉴스 이슈로 튀고, 방문자는 느리게 변한다.
그래서 서비스는 "상관은 있지만 인과는 아니다"라고 답하도록 설계했다.

## 3. 화면 구성

결론을 먼저 보여주고, 근거를 그다음에 놓았다.

| | 영역 | 하는 일 |
|---|---|---|
| 00 | **인사이트 밴드** | 첫 화면 상단. 한 문장 결론 + 핵심 수치 3개(최근 방문자 · 전년 동기 대비 · 대표 상관계수) |
| 01 | **인사이트 탭** | 이중 축 SVG 그래프(방문자 + 검색 지수), 사건 주석, 기간 필터(전체 / 최근 3년 / 코로나 이후), 상관계수 위계 표시 |
| 02 | **데이터 관리 탭** | 102건 목록, 추가 / 수정 / 삭제, CSV 내보내기 |
| 03 | **AI 채팅** | 추천 질문 칩, 로딩 표시, 대화 이어가기 |
| 04 | **대화 기록** | 채팅 패널에 통합. 목록 → 클릭해서 불러오기 → 삭제 |

그래프는 라이브러리 없이 인라인 SVG로 직접 그렸다. 사건이 있는 달은 점과 라벨로 표시하고,
라벨이 겹치면 건너뛰어 화면이 지저분해지지 않게 했다.

## 4. AI 기능 — 데이터 요약 컨텍스트 주입

`POST /api/chat`의 동작.

1. `build_summary()`로 요약 계산 — 기간 · 개수 · 통계 · 추세 · 상관계수 3종 · 사건 목록
2. 요약을 시스템 프롬프트에 삽입
3. 직전 대화 최대 10개와 함께 GPT 호출 (`max_completion_tokens` 500으로 제한)
4. 질문과 답변을 `conversations` 컬렉션에 자동 저장

실제로 주입되는 프롬프트의 일부.

```
[사용자 데이터 요약]
- 분석 기간: 2018-01 ~ 2026-06
- 데이터 개수: 102개월
- 방문자 지표: 평균 219,898명 / 최대 287,232명 / 최소 164,668명 / 최근 231,394명
- 최근 추세: 최근 3개월(2026-04~2026-06) 평균이 전년 동기(2025-04~2025-06) 대비 -4.4% (감소)
- 지표 간 상관관계:
  - 성심당 검색 지수: r=0.471 (뚜렷한 양의 상관관계, 2018-01 ~ 2026-06, 102개월)
  - 외국인 방문자: r=0.784 (강한 양의 상관관계, 2020-01 ~ 2026-06, 78개월)

[데이터에 기록된 주요 사건]
  - 2020-02: 코로나19 국내 확산 시작 (해당 월 방문자 185,964명)
  - 2023-08: 제1회 대전 0시 축제 개최 (해당 월 방문자 222,613명)
```

### 사건 주입 전후 비교

같은 질문 "2020년에 방문자가 줄어든 이유가 뭐야?"에 대한 답변이다.

| | 답변 |
|---|---|
| **주입 전** | "2020년 방문자 수 감소 원인은 주어진 데이터에 포함되어 있지 않습니다." |
| **주입 후** | "코로나19 국내 확산(2020-02)과 사회적 거리두기 시행(2020-03) 시기에 해당하며, 해당 월 방문자 수가 각각 185,964명과 165,843명으로 크게 줄었습니다. (...) 다만 상관관계만으로 인과관계는 판단할 수 없습니다." |

### 실패 처리

| 상황 | HTTP | 사용자에게 보이는 것 |
|---|---|---|
| 같은 달 데이터 중복 추가 | 409 | "2026-06 데이터가 이미 있습니다." |
| 잘못된 연월(`2099-13`) · 음수 방문자 | 422 | 입력값 검증 메시지 |
| 없는 데이터 수정 · 삭제 | 404 | "2019-99 데이터를 찾을 수 없습니다." |
| 수정할 필드가 비었을 때 | 400 | "수정할 필드가 없습니다." |
| 없는 대화 ID로 질문 | 404 | "대화를 찾을 수 없습니다." |
| OpenAI 키 누락 · 호출 실패 | 502 | "GPT 호출에 실패했습니다: …" |
| 서버 절전(콜드스타트) | — | `/health`를 3회 재시도하며 "서버를 깨우는 중 (최대 1분)" 안내 |

## 5. 기술 스택

| 층 | 사용 |
|---|---|
| 백엔드 | **FastAPI** · Pydantic v2 · Uvicorn (Python 3.11) |
| 데이터베이스 | **Firebase Firestore** (firebase-admin) |

| 배포 | 백엔드 **Render** · 프론트엔드 **Vercel** (GitHub 자동 배포) |

라우터는 HTTP 관심사만, 서비스는 도메인 로직만 갖도록 나눴다.
그래서 챗봇은 `/api/data/summary`를 HTTP로 다시 부르지 않고 `analytics.build_summary()`를 직접 호출한다.

## 7. 데이터 파이프라인

| 단계 | 스크립트 | 내용 |
|---|---|---|
| 수집 | `fetch_region_visitors.py` | 공공데이터포털 광역 일별 방문자 (2018-01~, 8,735건) |
| 수집 | `fetch_district_visitors.py` | 대전 5개 구 일별 방문자 (2024-01~, 14,460건) |
| 수집 | (수동) | 네이버 데이터랩에서 "성심당" 일별 검색 지수 엑셀 다운로드 |
| 정제 | `prepare_dataset.py` | 일별 → 월별 집계, 세 소스 병합, 사건 메모 부착 |
| 적재 | `seed_firestore.py` | 배치 쓰기로 Firestore 적재 (문서 ID = 연월이라 재실행해도 중복 없음) |

수집 API에 지역 필터 파라미터가 없어 전국을 받아 대전만 걸러낸다.
개발계정 일일 호출 한도(1,000회)를 넘지 않도록 기간을 나눠 호출한다.

### 데이터 항목

| 필드 | 내용 | 기간 |
|---|---|---|
| `value` | 대전 외지인 방문자 일평균 | 2018-01 ~ 2026-06 (**102개월**) |
| `ref_value` | "성심당" 검색 지수 (최댓값 100 기준) | 2018-01 ~ 2026-06 |
| `foreign_value` | 대전 외국인 방문자 일평균 | 2020-01 ~ |
| `junggu_share` | 대전 5개 구 중 중구 방문자 비중(%) | 2024-01 ~ |
| `memo` | 코로나 조치 · 대전 0시 축제 등 사건 | 해당 월만 |

값이 없는 달은 **0이 아니라 필드를 비워 둔다.** 0으로 채우면 "2019년 외국인 0명"이라는 잘못된 답이 나온다.

## 8. API

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/health` | 서버 상태 확인 (콜드스타트 대비) |
| GET | `/api/data` | 데이터 목록 (연월 오름차순, `limit` 지원) |
| POST | `/api/data` | 데이터 추가 (문서 ID = 연월, 중복 시 409) |
| PUT | `/api/data/{id}` | 부분 수정 (전달한 필드만 반영) |
| DELETE | `/api/data/{id}` | 삭제 |
| GET | `/api/data/summary` | 요약 — 통계 · 추세 · 상관계수 · 사건 목록 · 주의사항 |
| POST | `/api/chat` | AI 대화 (요약 주입 + 자동 저장) |
| GET | `/api/conversations` | 대화 목록 (본문 제외) |
| POST | `/api/conversations` | 대화 저장 |
| GET | `/api/conversations/{id}` | 특정 대화 전체 메시지 조회 |
| DELETE | `/api/conversations/{id}` | 대화 삭제 |

`/api/data/summary`는 `/api/data/{id}`보다 **먼저 선언**해야 `summary`가 ID로 해석되지 않는다.

## 9. 로컬 실행

```bash
# 1) 백엔드
cd backend
python -m venv .venv
.venv\Scripts\activate           # macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
copy .env.example .env           # macOS/Linux: cp .env.example .env
#   .env 에 OPENAI_API_KEY 와 FIREBASE_SERVICE_ACCOUNT_PATH 를 채운다
uvicorn main:app --reload        # http://localhost:8000/docs

# 2) 프론트엔드 (다른 터미널)
cd frontend
python -m http.server 5500       # http://localhost:5500
```

프론트엔드는 `localhost`에서 열면 자동으로 로컬 백엔드(`http://localhost:8000`)를 바라본다.
백엔드의 `ALLOWED_ORIGINS` 기본값에 `http://localhost:5500`이 들어 있다.

```bash
# 3) Firestore 연결만 확인하고 싶을 때
pip install -r requirements-dev.txt
python -m scripts.check_firebase
```

## 10. 배포

### 백엔드 (Render)

| 항목 | 값 |
|---|---|
| Root Directory | `backend` |
| Build Command | `pip install -r requirements.txt` |
| Start Command | `uvicorn main:app --host 0.0.0.0 --port $PORT` |
| Instance | Free |
| Secret File | `firebase-service-account.json` (JSON 원본 붙여넣기 → `/etc/secrets/`에 생성) |

서비스 계정 키는 환경 변수에 한 줄로 밀어 넣지 않고 **Secret File**로 올린 뒤 경로만 환경 변수로 넘긴다.

### 프론트엔드 (Vercel)

`frontend/vercel.json`이 빌드 설정을 갖고 있다.

```json
{
  "buildCommand": "echo \"window.API_BASE_URL='$API_BASE_URL';\" > config.js",
  "outputDirectory": ".",
  "cleanUrls": true
}
```

정적 사이트라 별도 빌드가 없으므로 `outputDirectory`를 `.`로 고정해야 한다.
빌드 단계에서 환경 변수 `API_BASE_URL`을 `config.js`에 주입한다.

> **배포 후 반드시** Render의 `ALLOWED_ORIGINS`에 Vercel 도메인을 추가한다.
> 빠뜨리면 화면은 뜨지만 데이터가 하나도 보이지 않는다.

## 11. 환경 변수

| 이름 | 필수 | 설명 |
|---|---|---|
| `OPENAI_API_KEY` | ✅ | OpenAI API 키 |
| `OPENAI_MODEL` | | 기본 `gpt-4.1-mini` |
| `OPENAI_MAX_TOKENS` | | 응답 토큰 상한, 기본 500 |
| `FIREBASE_SERVICE_ACCOUNT_PATH` | 둘 중 하나 | 서비스 계정 JSON 경로 (로컬 · Render Secret File) |
| `FIREBASE_SERVICE_ACCOUNT_JSON` | 둘 중 하나 | 서비스 계정 JSON 문자열 |
| `ALLOWED_ORIGINS` | ✅ | CORS 허용 도메인, 쉼표 구분 |
| `API_BASE_URL` | ✅ (Vercel) | 프론트가 바라볼 백엔드 주소 |
| `DATA_GO_KR_API_KEY` | | 공공데이터포털 인증키 (수집 스크립트 전용) |

키는 코드·저장소·스크린샷 어디에도 넣지 않는다.
`.gitignore`가 `.env`와 `*firebase-adminsdk*.json`을 제외하며, 커밋 전에 `git check-ignore`로 확인했다.

> 키가 유출된 것 같으면
> ① 발급처에서 즉시 폐기·재발급 → ② Render/Vercel 환경 변수 교체 후 재배포
> → ③ 커밋 이력에 남았다면 히스토리에서 제거 후 강제 푸시

## 12. 설계에서 신경 쓴 점

| 문제 | 선택 |
|---|---|
| 계절성이 강한 데이터라 직전 3개월 비교는 계절 변동을 추세로 오해하게 만든다 | 추세를 **전년 동기 대비**로 계산하고, 비교한 두 구간을 응답에 함께 담았다 (AI가 기간을 추측하지 않도록) |
| 지표마다 집계 기간이 달라 상관계수를 한 숫자로 말하면 오해를 부른다 | 상관계수마다 **계산 구간과 표본 수**를 함께 응답 |
| 같은 달을 두 번 넣는 실수 | Firestore 문서 ID를 연월로 써서 **중복이 구조적으로 불가능**하게 만들고, 시드 스크립트도 재실행 가능하게 함 |
| 목록 API가 대화 본문까지 주면 무거워진다 | 목록은 메타데이터만, 본문은 `GET /api/conversations/{id}`로 분리 |
| Render 무료 인스턴스의 콜드스타트 | 프론트가 진입 시 `/health`를 재시도하며 안내 문구 표시 |
| Firebase 초기화 실패가 서버 기동 자체를 막는 문제 | Firestore 클라이언트를 **첫 요청 시 지연 초기화**해서, 키 설정 전에도 `/docs`는 열리게 함 |

## 13. 테스트 케이스

| 입력 | 기대 결과 |
|---|---|
| "2020년에 방문자가 줄어든 이유가 뭐야?" | 코로나19 확산·거리두기를 **memo 근거로** 설명 |
| "성심당 검색량과 방문자는 관계가 있어?" | r=0.471과 **계산 구간**을 밝히고, 인과로 단정하지 않음 |
| 데이터 추가 → 수정 → 삭제 | 102 → 103 → (수정 반영) → 102건, 그래프·요약 즉시 갱신 |

## 14. 데이터 출처와 한계

- **방문자 수** — 공공데이터포털 [한국관광공사 빅데이터 지역별 방문자수](https://www.data.go.kr/data/15101972/openapi.do). KT(내국인)·SKT(외국인) 이동통신 기반 **추정치**이며, 같은 사람이 2박 3일 머물면 3명으로 집계된다. 절대량이 아니라 추세로 읽어야 한다.
- **검색 지수** — [네이버 데이터랩 검색어 트렌드](https://datalab.naver.com/keyword/trendSearch.naver). 실제 검색 횟수가 아니라 기간 내 최댓값을 100으로 둔 **상대 지표**이며, 방문이 아니라 관심을 나타낸다.
- **관광지점 입장객 통계** — [관광지식정보시스템](https://know.tour.go.kr/stat/visitStatDis/table.do). 비교 검증용으로만 사용했다. 집계 대상 관광지가 시기별로 바뀌어 시계열로 쓰기 어렵다.
- 상관관계는 인과관계가 아니다. 두 지표 모두 시간에 따라 증가하는 추세라 공통 추세가 상관을 부풀렸을 수 있다.
